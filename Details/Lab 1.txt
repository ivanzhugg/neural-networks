ШАГ 2. Определение смысла массивов

Требование: заранее понимать формы результатов, а не только получить работающий код.

Действие: заполнена таблица форм:
X @ W1: (8, 5).
X @ W1 + b1: (8, 5).
(X @ W1 + b1) @ W2: (8, 3).

Исходные формы:
X (8, 4): восемь объектов, четыре входных признака.
W1 (4, 5): веса от четырёх признаков к пяти скрытым нейронам.
b1 (5,): пять смещений скрытого слоя.
W2 (5, 3): веса от пяти скрытых признаков к трём классам.
b2 (3,): три выходных смещения.
y (8,): правильный класс каждого объекта.

Обоснование: для матричного произведения внутренние размеры совпадают: (B, D) @ (D, H) даёт (B, H). Каждая строка результата относится к одному объекту.

Веса одного скрытого нейрона находятся в одном столбце W1. Элемент Z1[i, j] равен сумме X[i, k] * W1[k, j] по четырём входным признакам плюс b1[j]. Так рассчитывается взвешенная сумма признаков для нейрона j объекта i.

Разница между * и @ принципиальна. Для векторов [1, 2, 3] и [4, 5, 6] операция * даёт [4, 10, 18], а @ даёт сумму 4+10+18=32. Линейному слою нужна сумма произведений, поэтому используется @.

ШАГ 3. Линейный слой и broadcasting

Требование: реализовать linear_batch без циклов.

Действие:
def linear_batch(X, W, b):
    return X @ W + b

Обоснование: NumPy сразу вычисляет выходы слоя для всех строк. Вектор b формы (H,) прибавляется к матрице (B, H) через broadcasting.

Broadcasting сравнивает размеры справа. Размеры по каждой оси должны совпадать либо один из них должен быть равен 1. Отсутствующая слева ось считается единичной. Поэтому (H,) ведёт себя как (1, H) и применяется к каждой строке.

Вектор (B,) обычно не подходит: он сравнивается с последней осью H. При B=8 и H=5 возникает несовместимость. Вектор (B, 1) можно прибавить, но это означало бы отдельное смещение каждого объекта, а не каждого нейрона. Если B случайно равен H, неправильная форма может не вызвать ошибки, поэтому нужно понимать смысл осей.

Проверка: встроенные assert проверяют форму Z1 и сравнивают первую строку с X[0] @ W1 + b1. Дополнительно весь результат проверен через np.einsum, который независимо записывает ту же сумму по входным признакам.

ШАГ 4. ReLU и sigmoid

Требование: реализовать две поэлементные функции без циклов.

Действие:
def relu(x):
    return np.maximum(0, x)

def sigmoid(x):
    return 1 / (1 + np.exp(-x))

Обоснование: ReLU(x)=max(0, x) обнуляет отрицательные элементы и сохраняет положительные. Каждый входной элемент даёт один выходной, поэтому форма не меняется. A1=relu(Z1) имеет форму (8, 5).

Sigmoid(x)=1/(1+exp(-x)) преобразует обычные конечные значения к интервалу между 0 и 1. При x=0 результат 0.5. Для [-2, 0, 2] получаются примерно [0.1192, 0.5, 0.8808].

Нелинейная активация нужна потому, что два линейных слоя без неё можно объединить в один:
(X @ W1 + b1) @ W2 + b2 = X @ (W1 @ W2) + b1 @ W2 + b2.
ReLU нарушает эту сводимость и позволяет описывать нелинейные зависимости.

Sigmoid реализована для отдельного задания; в самой сети используется ReLU. Простая sigmoid достаточна для заданных входов. При очень больших отрицательных значениях exp(-x) может переполниться. ТЗ отдельно требует устойчивость softmax, а не универсальную защиту sigmoid от любых экстремальных входов.

Проверка: обе функции выполнены для скаляра, вектора и матрицы. Формы сохранены. ReLU дополнительно сопоставлена с np.where, sigmoid с эквивалентной формулой через tanh.

ШАГ 5. Устойчивый softmax

Требование: получить вероятности классов отдельно для каждого объекта и избежать переполнения экспоненты.

Действие:
shifted = logits - logits.max(axis=1, keepdims=True)
exp_logits = np.exp(shifted)
probs = exp_logits / exp_logits.sum(axis=1, keepdims=True)

Обоснование: logits являются произвольными оценками классов. Они не обязаны лежать между 0 и 1 или суммироваться до 1. Softmax делит экспоненту каждого класса на сумму экспонент всех классов этого объекта.

axis=1 сворачивает столбцы, то есть классы. keepdims=True сохраняет результат максимума или суммы в форме (B, 1). Так один максимум вычитается из всей соответствующей строки, а одна сумма используется для нормировки этой строки.

Без keepdims результат имел бы форму (B,), обычно несовместимую с (B, C). axis=0 нормировал бы значения между разными объектами, что не даёт нужного распределения классов для каждой строки.

Почему сдвиг не меняет ответ:
exp(z_c-m) / sum(exp(z_j-m))
= exp(z_c)*exp(-m) / (exp(-m)*sum(exp(z_j))).
Множитель exp(-m) сокращается.

Для [1000, 1001, 1002] сначала получаются [-2, -1, 0]. Максимальная экспонента равна 1, поэтому переполнения не возникает. Результат примерно [0.0900, 0.2447, 0.6652].

Проверка: вероятности конечны, неотрицательны, не превышают 1 и суммируются по строкам до 1. Дополнительно проверена неизменность softmax после добавления разных общих констант к отдельным строкам.

ШАГ 7. Cross-entropy

Требование: выбрать вероятность правильного класса каждого объекта и усреднить -log(p).

Действие:
p_true = probs[np.arange(len(y)), y]
p_true = np.clip(p_true, eps, 1.0)
return -np.log(p_true).mean()

Обоснование: np.arange(len(y)) даёт индексы строк. Второй массив y даёт правильные столбцы. Индексы используются попарно: probs[0,y[0]], probs[1,y[1]] и так далее. Получается один элемент для каждого объекта без цикла.

np.clip не позволяет вызвать log(0). При eps=1e-12 максимальный вклад ограничен примерно 27.631. В математической формуле без clip вклад при p -> 0 стремится к бесконечности. При p -> 1 он стремится к нулю.

Например, при вероятностях правильного класса 0.9, 0.5 и 0.1 вклады равны примерно 0.1054, 0.6931 и 2.3026. Чем хуже оценивается правильный класс, тем больше штраф.

Проверка: для равномерного распределения по трём классам ошибка равна log(3). Для правильного класса с вероятностью 1 ошибка равна 0. Нулевая вероятность даёт конечное значение -log(eps). Ошибка всей сети также сравнена с прямым суммированием по восьми объектам.

ШАГ 9. Цикл и векторизация

Требование: сравнить две эквивалентные реализации линейного слоя.

Действие: linear_loop выделяет массив формы (число объектов, число выходов), проходит по объектам и записывает X[i] @ W + b. linear_vectorized возвращает X @ W + b одной строкой.

np.empty не заполняет массив готовыми значениями. Поэтому перед возвратом каждая строка записывается циклом. Векторизованная версия поручает обработку всего массива NumPy и используемой численной библиотеке.

Benchmark использует X_bench (20000, 64), W_bench (64, 32), b_bench (32,). До измерений вычислены обе версии и проверено совпадение. Затем каждая функция запускается трижды, берётся минимальная длительность по time.perf_counter.

Обоснование: Python-цикл создаёт накладные расходы на каждую строку. Матричная операция целиком лучше использует оптимизированные численные алгоритмы. Конкретное ускорение зависит от CPU, BLAS, размера данных и нагрузки. ТЗ не устанавливает обязательного порога ускорения.

np.allclose нужен из-за округления вещественных чисел и различного порядка суммирования. Математически равные выражения могут немного отличаться в памяти. Точное == бывает излишне строгим.

Актуальные времена находятся в сохранённом выводе notebook и его кратком ответе. При новом запуске они изменятся, поэтому фиксированное время не является частью проверки корректности.

ЧАСТЬ 3. ЧТО ОБЪЯСНИТЬ НА ЗАЩИТЕ

1. Почему X @ W1 имеет форму (8, 5)? Внутренний размер 4 совпадает, остаются восемь объектов и пять выходов.
2. Почему bias одинаков для всех строк? Это параметр нейрона, а не отдельного объекта.
3. Зачем ReLU между слоями? Она добавляет нелинейность.
4. Чем logits отличаются от probabilities? Первые являются оценками, вторые нормированы по классам.
5. Зачем axis=1 и keepdims=True? Для отдельной нормировки каждой строки и правильного broadcasting.
6. Зачем вычитать максимум? Для устойчивой экспоненты без изменения вероятностей.
7. Что выбирает probs[np.arange(len(y)), y]? Вероятность правильного класса каждого объекта.
8. Почему ошибка растёт при p -> 0? -log(p) сильно штрафует малую вероятность правильного класса.
9. Почему сравнение через allclose? Из-за ограниченной точности вещественных вычислений.

Примеры изменения кода:
При B=10 веса сохраняют формы, но X и y должны содержать десять объектов.
При H=7 меняются W1, b1, скрытый массив и первая ось W2.
При C=4 выход получает четыре столбца, метки должны быть от 0 до 3.
Замена @ на * меняет смысл операции и обычно приводит к ошибке форм.
Добавление константы ко всем logits одной строки сохраняет softmax; умножение на константу обычно меняет уверенность распределения.
